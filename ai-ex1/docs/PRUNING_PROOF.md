# Pruning proof for the current `ex1.py`

This document describes only the pruning rules that remain in the current implementation.
The earlier history-dependent normal forms were removed after finding retained states whose optimal
continuation was destroyed by those rules.

The heuristic is proved separately in `ADMISSIBILITY_PROOF.md`.

## 0. Scope

The current successor generator uses the following reductions:

| Rule                                                                    | Implementation                         | Status in this document                                                          |
| ----------------------------------------------------------------------- | -------------------------------------- | -------------------------------------------------------------------------------- |
| R1. Never LOAD a package already lying at its goal                      | goal packages are omitted from `lying` | proved below                                                                     |
| R2. Eager goal UNLOAD                                                   | `OPT_FORCED` / `_truck_standing`       | proved below                                                                     |
| R3. Identical-object representatives                                    | `OPT_TWINS`                            | proved below                                                                     |
| R4. Dead bridge sides and dominated ports                               | `OPT_DEAD`                             | global optimal-plan proof below; stronger course interpretation still to confirm |
| R5. Independent connected components                                    | `OPT_COMP` / `_finish`                 | global optimal-plan proof below; stronger course interpretation still to confirm |
| R6. Endpoint-only transfers on empty road corridors                     | `OPT_CORRIDOR`                         | global optimal-plan proof below; stronger course interpretation still to confirm |
| S. Merge states differing only by a renaming of interchangeable objects | `OPT_SYM` / `_canon`                   | proved below                                                                     |

`OPT_BARREN` is disabled. `OPT_FIRST` belongs to the heuristic and is not successor pruning.

The following old rules are **not part of the current algorithm or proof**:

- truck focus after DRIVE/LOAD;
- unload-before-load history ordering;
- immediate U-turn prohibition;
- fresh-board prohibition on immediate DISEMBARK;
- forced BOARD after an empty ferry repositioning sail.

The state tuple still has a leading zero for compatibility with the original tuple layout, but it stores no
action history.

The course staff clarified that package weights are positive (at least 1) and that every ferry starts at a
port it serves. The proof below uses those assignment-domain assumptions.

## 1. Two different optimality statements

Let `G0` be the full world transition graph: every state is a physical logistics state and every edge is one
world-legal action. Let `G1` be the graph generated by the current successor function, modulo the state
symmetry `S`.

There are two properties that should not be confused:

1. **Initial optimality preservation:** at least one minimum-cost plan from the designated initial state is
   still represented in `G1`.
2. **Per-retained-state preservation:** for every retained state `s`, the cheapest continuation from `s` in
   `G1` has the same cost as the cheapest continuation from the corresponding world state in `G0`.

The removed history-dependent rules fail property 2. This document does not use them.

For R4-R6, the arguments below establish property 1. Whether the assignment requires the stronger property
2 for these structural reductions should be confirmed with the course staff.

## 2. Lemma 0 — generated actions are world-legal

Every generated action satisfies the assignment preconditions:

- DRIVE is generated only for a standing truck and an allowed road neighbour;
- LOAD is generated only for a package lying at the truck's location whose addition keeps the truck within
  capacity;
- UNLOAD is generated only for a package currently inside that standing truck;
- BOARD is generated only when truck and ferry are at the same port and the ferry has a free truck slot;
- DISEMBARK is generated only for a truck aboard a ferry, and places it at the ferry's current port;
- SAIL is generated only between distinct ports served by that ferry.

The generated tuple changes exactly the objects affected by that action. The component write-back of R5 is
bookkeeping for components that will never act again; a goal-reaching search path can be replayed in the
world without performing those write-backs.

Therefore every goal-reaching search path corresponds to a legal world plan of the same action cost. ∎

## 3. R1 — never load a package already at its goal

Suppose a plan LOADs a package `p` while `p` is already lying at its goal. Since the final state also requires
`p` at that same location, the plan must later return `p` there. Remove that LOAD and every later action that
only moves `p` between trucks and its already-satisfied goal location. Other trucks only gain capacity; no
precondition becomes harder to satisfy.

The resulting plan is no more expensive and still reaches the goal. Thus some optimal plan never LOADs a
package already lying at its goal. ∎

## 4. R2 — eager unloading at a package goal

Suppose truck `t` stands at location `l` and carries package `p` whose goal is `l`. Consider a cheapest
continuation from this physical state.

If it does not unload `p` immediately, move the first future `UNLOAD(p,t)` to the front and delete any later
LOAD/UNLOAD actions of `p`. This is legal because:

- `p` is already in `t` now;
- after unloading it at its goal, no future action needs to move it again;
- package weights are positive, so unloading can only free truck capacity.

The cost does not increase. Therefore an optimal continuation exists whose next action is an UNLOAD of a
goal-bound package carried by a standing truck.

If several such packages are available, their UNLOAD actions commute: each places one already-carried
package at the same truck location and only decreases the load. Therefore choosing a canonical one first
preserves an optimal continuation. ∎

## 5. R3 and S — identical objects and canonical state merging

### 5.1 Object classes

The implementation regards objects as interchangeable only when their static data relevant to future legal
actions agree:

- trucks: same effective capacity;
- packages: same weight and same goal;
- ferries: same served-port set and same effective truck capacity.

The twin rule is applied only when the interchangeable objects are also in the same current situation, e.g.
packages at the same place, empty trucks at the same place, or empty ferries at the same port.

### 5.2 Renaming argument

Let `sigma` be a permutation that exchanges two such interchangeable objects and fixes all others. Because
all action preconditions, effects, capacities and goals are preserved by `sigma`, every legal continuation

`a1, a2, ..., ak`

from state `s` maps to the renamed continuation

`sigma(a1), sigma(a2), ..., sigma(ak)`

from `sigma(s)`, with the same costs and a goal iff the original continuation reaches a goal.

Therefore states related only by such a renaming have identical optimal remaining cost.

When the twin rule keeps only the lowest-numbered representative, take any cheapest continuation beginning
with another twin and rename that twin with the retained representative. The renamed continuation has the
same cost and starts with the generated action.

Thus `OPT_TWINS` and `_canon` do not lose optimal cost. ∎

## 6. R4 — dead bridge sides and dominated ports

This is a global optimal-plan normalization.

### 6.1 Dead bridge sides

Build the auxiliary map graph containing road-location vertices, ferry vertices, road edges, and
port-ferry edges. Mark:

- every initial truck location;
- every initial package location;
- every package goal.

A side of a bridge containing no mark is a dead side. It contains no resource or delivery requirement that
an optimal plan needs to obtain there.

Take an optimal world plan and consider a maximal excursion into such a side. Project all locations inside
the dead side to its attachment point on the live core. Internal DRIVE/SAIL actions that become no-ops are
deleted; LOAD/UNLOAD actions are performed at the attachment point instead. Since no package starts or ends
inside the dead side and no truck starts there, this projection preserves all required package deliveries
and never increases cost.

Applying this to every dead side produces an optimal plan that never enters them.

### 6.2 Dominated empty ports

For an unmarked road island with no initially docked ferry, the implementation removes a port only when
there is a nondead substitute port served by every ferry participating in the removed island. Replace every
visit to the removed island by the substitute port. Trucks and ferries that were colocated on the island
remain colocated at the substitute, and any sail that collapses to no movement is deleted. The cost does not
increase.

Therefore at least one globally optimal initial plan survives `OPT_DEAD`. ∎

**Open point:** this argument proves existence of a surviving optimal initial plan. The course staff should
confirm whether their successor requirement additionally demands equality of optimal suffix cost from every
retained state.

## 7. R5 — independent map components

Two different connected components of the auxiliary map graph share no road, ferry route, truck, or package.
No action in one component changes a precondition or effect in another component.

Hence actions from different components commute. Starting with an optimal plan, repeatedly swap actions of
lower-ranked components past actions of higher-ranked components until each component is solved in the
chosen canonical order. The multiset of actions and therefore the cost is unchanged.

After a component is finished, its objects never act again in this canonical plan. `_finish` resets their
stored positions only to improve state merging; those positions are never subsequently read for an acting
object. Replaying the action sequence in the physical world therefore remains legal.

Thus at least one globally optimal initial plan survives `OPT_COMP`. ∎

**Open point:** as with R4, confirm whether the course requires the stronger per-retained-state property and
whether the nonphysical `_finish` representation is acceptable under that interpretation.

## 8. R6 — transfers only at corridor endpoints

An anchor is a road location that is any of:

- road degree different from two;
- an initial truck location;
- an initial package location;
- a package goal;
- a ferry port.

The interior of a path between two anchors is therefore an initially empty degree-two road corridor with no
package goal or ferry port inside it.

Fix one such corridor of `L` road edges. For each threshold `j=1,...,L`, map corridor vertices on one side of
edge `j` to the left endpoint and vertices on the other side to the right endpoint. Under this mapping,
transfers inside the corridor move to endpoints. A DRIVE that collapses to one endpoint is deleted; a DRIVE
that crosses the threshold is expanded to the full `L`-edge traversal.

If edge `j` was traversed `N_j` times in the original plan, the transformed plan for threshold `j` pays
`L*N_j` corridor DRIVEs. Averaging over all `L` thresholds gives exactly

`sum_j N_j`,

the original corridor-driving cost. Therefore at least one threshold transformation does not increase the
cost. Apply this independently to every corridor.

So at least one globally optimal plan exists in which package transfers occur only at anchors, exactly the
restriction implemented by `OPT_CORRIDOR`. ∎

**Open point:** this is again a global normalization argument. Confirm the stronger per-retained-state
interpretation with course staff.

## 9. A\* optimality for the pruned graph

Let `V(s)` be the cheapest goal-reaching cost in the current pruned graph. `_canon` equality preserves
`V` by Section 5. The heuristic proof gives `h(s) <= V(s)` for every reachable search state because every
pruned continuation is also a world continuation and the heuristic lower-bounds unrestricted world
completion cost.

The supplied graph-search implementation reopens an equal state when it is reached at a strictly smaller
path cost. Therefore consistency of `h` is not required.

Assume the structural rules R4-R6 are accepted under the assignment's pruning requirement. Sections 3-8
show that some original optimal initial plan survives in the pruned graph. Standard A\* with an admissible
heuristic and reopening then returns a goal with exactly that optimum cost. ∎

## 10. Removed rules and why they were removed

The following are intentionally absent from the theorem.

### Truck focus after DRIVE/LOAD

A retained state can be reached by moving a low-capacity truck to a package location while another truck
there is the only one capable of carrying the package. Forcing the truck that just moved to act again can
make the retained state unsolvable even though its physical world has a short optimal continuation using
the other truck.

### Immediate U-turn prohibition

A retained state reached by a nonoptimal DRIVE can have an immediate return DRIVE as its cheapest
continuation. Forbidding that return increases the optimal suffix cost.

### Unload-before-load history rule

Once a LOAD has already happened and that resulting state is retained, an immediate UNLOAD of some cargo
can be the cheapest transfer action. A rule that forbids UNLOAD merely because the preceding action was a
LOAD is therefore not valid under the per-retained-state interpretation.

### Fresh BOARD restriction

After a retained BOARD state, immediately DISEMBARKing can be the cheapest way to undo a bad BOARD. Forcing
a SAIL first can increase the optimal suffix cost.

### Forced BOARD after an empty-ferry sail

After the sail state itself is retained, the cheapest continuation need not BOARD the waiting truck. A
pending state that allows only BOARD can therefore destroy an optimal suffix.

### Barren-side pruning

The old proof relied on truck focus: after an empty truck crossed a bridge, only that truck could act until
it LOADed or BOARDed. With focus removed, that proof no longer applies. The optimization is disabled until a
new independent proof is available.

## 11. Validation still needed

Random/exhaustive testing is useful evidence but is not a substitute for the proofs above. For the current
version, the strongest useful regression check is:

1. enumerate small physical world states with an independent exact solver;
2. enumerate the states retained by the current successor generator;
3. for each retained state, compare the exact optimal world suffix cost with the exact pruned suffix cost.

That directly tests the stronger interpretation stated by the course staff.
